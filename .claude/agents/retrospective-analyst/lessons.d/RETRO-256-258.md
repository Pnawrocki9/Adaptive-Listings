## A finding I almost missed, and why

**The fired-at-birth re-review trigger in `dpia.md` §2.7.3 (RETRO-256 §4d DG-1).** The brief told me
to sweep compliance docs for triggers that cannot distinguish their firing condition from the world
they were written in. My first instinct was to grep for the _phrase_ the PM had fixed ("already
survive it") — which would have returned exactly one hit, the one already corrected, and I would
have written "clean, no siblings". What found it was greping for the **structure**
(`Re-review trigger`) and then reading all fourteen triggers as logic rather than as prose. The one
that fired had no phrase in common with the one the PM caught; it fires because its `including`
clause enumerates instances of its own head clause.

**The general lesson for me: when a brief hands me a defect and asks for siblings, the sibling set
is defined by the DEFECT'S SHAPE, not by the defect's WORDS.** That is P-36 (RETRO-251) turned on my
own sweeps — my predecessor minted it about workers' enumerations and I nearly committed the same
error one retro later. I now write the structural grep first and the phrase grep second, never the
reverse.

Worse: **RETRO-251 read that exact section closely enough to correct its own brief's premise from
it, and RETRO-253 re-read it.** Two of my predecessors had the file open. The axis existed and
nobody was looking down it, because both were checking _citations_ (§4d, line numbers) and not
_trigger logic_.

## An axis / chain I had to trace twice

**The `consent_records` verdict (RETRO-257).** The count is zero; the brief asked me to decide
between "not calling", "calling and failing", and "no traffic". My first pass reasoned from the
count plus the CEO's localhost-first framing and reached "never integrated" — a plausible inference
from two facts that do not actually discriminate between the three options. The count is equally
consistent with all three.

I traced it a second time looking for something that _could only be true_ in one of the three
worlds, and found it in a file the same PR had edited: `backlog/HANDOFFS.md:2973` — _"Auth secret:
`PLATFORM_REGISTRATION_CONSENT_SECRET` — request from Piotr (to be provisioned in Doppler)"_, still
in the **future tense**. Without the shared secret the caller cannot sign and cannot pass
`route.ts:155`. That is a discriminating fact; the count is not.

**Lesson: when a brief offers me N explanations, my job is to find the evidence that RULES OUT N−1,
not the evidence CONSISTENT WITH the one I find most likely.** I had written a paragraph of the
consistent kind before I caught myself.

The second trace on the same chain: I initially read FOLLOW-706's stub as simply having guessed
wrong. Re-reading it, the error is a specific and nameable inference — _"#634 changed the behaviour
of ZERO live requests, **i.e.** every live consent record still carries the placeholder"_ — where
the "i.e." is invalid, and the stub's own AC(1) had already named the correct reading as "a real
possible outcome". **A stub argued against its own AC and the narrative won for eleven days.** That
is a much sharper finding than "the estimate was wrong", and it took the second pass.

## A meta-pattern in how gaps recur across agents

**Three consecutive retros have now found a corrective edit that did not reach a line the author was
demonstrably sitting on** — RETRO-252 §4d DG-2 (four lines added to a code block four lines below a
false sentence), RETRO-255 §4d DG-2 (a +1/−1 diff on the very line carrying a stale count), and this
batch **twice in one merge**: `.gitleaks.toml`'s two-line tail still instructing the reader to
update a tag the paragraph above says was REMOVED, and `consent-banner.ts:148`'s enumeration bullet
still asserting "no raw chat text stored by AL" three lines above the correction appended to the
same docblock.

I deliberately did **not** mint a pattern for it: all four are instances of **Rule AO**, which
exists and which, run verbatim, reports each of them not clean. **Sixth consecutive retro to reach
"compliance failure against an adequate control".** The meta-pattern is not the defect — it is that
this estate's rule _texts_ keep being adequate and its rule _execution_ keeps not happening, and I
should stop treating each new instance as a candidate pattern. **My default on seeing a doc-drift
shape is now: read Rule AO / AI / S / Y verbatim FIRST and only mint if all four report clean.**

Second meta-pattern, and it cuts the other way: **the two most valuable findings of this batch came
from workers, not from retros.** #688's feature-composition catch (the grace band composed with the
derived hash) and #689's rejection of the brief's option 1 were both worker-originated, both against
the record, and both accepted without argument. RETRO-251 first named the retro-driven →
worker-driven switch; it has now held for eight consecutive merges. **My value is shifting from
finding defects to adjudicating rules, tracing closures end-to-end, and driving perturbations the
workers cannot run against their own merged code.** Three of this batch's five headlines are
perturbation results (RETRO-258 §2 runs 2–6), and none of them was available to the worker before
merge.
