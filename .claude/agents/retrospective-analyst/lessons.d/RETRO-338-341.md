# RETRO-338..341 — 2026-09-21 (#916, #917, #919, #921)

## A finding I almost missed, and why

**The stale `dist` on the MAIN checkout.** #922's §6.9 had already found the stale-dist trap. It
framed it as a worktree problem, and I nearly took that framing on trust. What changed my mind was
checking the actual file dates in the main checkout: `packages/db/dist/index.js` 2026-07-28,
`packages/shared/dist` 2026-09-21. That split is exactly what README §3.3's literal build line
produces (shared + sdk only). A trap that someone else has documented is a claim about its scope,
and the scope is the part to verify.

**The PR body's "only `.end()` caller".** The dispatch brief repeated it too. One grep for
`\$client\.end` found three callers, and `migrate.ts` uses `createAdminClient()`, not
`createClient()`. When the brief and the PR agree, that is one claim, not two.

## An axis / chain I had to trace twice

**FOLLOW-1240's holdout story.** On the first pass I accepted "a holdout session is not served an
adapted response" as the cause of the 30 s burn. That explains why `adapted-response` cannot fire.
It does not explain why `new-response` did not fire, and that exit should have ended the wait at the
floor. The second pass read where `postQuizStartIndex` is taken (after the loop's final
`sleep(1200)`) and set it against the ticket's own latencies (259–785 ms). The mechanism is
positional, and holdout is one input that triggers it. Lesson: when a filed ticket explains a
symptom, check that its explanation accounts for EVERY exit that failed to fire, not only the one it
names.

## A meta-pattern in how gaps recur across agents

**A closure is measured on the machine that was prepared for it.** Seeds (RETRO-332/337) and now
builds (RETRO-341) are both state outside git that the measuring session set up and the documented
procedure does not. The pattern recurs because the harness's freshness verdict grades the git tree,
which makes the machine state invisible to the one control that asserts "these are the bytes that
ran". Promoted as Rule AA amendment 1. The positive control is #917: it shipped the doc step AND a
preflight that refuses to run without the service, and its closure held on every later run.

## Process note

- A mutation pass on a `packages/*` file is cheap without touching the main checkout. Copy the
  package into `scratchpad/root/packages/<pkg>`, symlink `node_modules`, `packages/shared` and the
  root `tsconfig.base.json` (`tsconfig.json` extends `../../tsconfig.base.json`), and run the main
  checkout's vitest binary from there.
- Without the tsconfig symlink the suite reports "no tests", which looks like a pass.
