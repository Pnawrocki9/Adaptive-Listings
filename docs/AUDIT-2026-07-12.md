## 1. Executive Summary

The foundation is **sound, not scaffold-theater at the core**: the 18-archetype vocabulary is
byte-for-byte consistent everywhere it is defined, the adaptation engine is wired to 18 real
playbooks, the LLM description pipeline has strong layered fact-grounding and fails safe, and
security/GDPR/tenant-isolation are clean. The problem is **not the shell — it's that the adaptive
intelligence is not actually adaptive in production yet.** The learning loop is frozen (feedback
endpoint 503-gated → Thompson bandit stuck at uniform-random), archetype→listing affinity falls back
to a djb2 hash because the embedding vectors are NULL-seeded, ~48% of the event schema is dead, and
the real-time chat-NLP path is starved because the Redpanda transport is a documented no-op. None of
this is rework — it is finishing work plus an operator go-live that is **0/6 complete**.

**Verdict: 🟡 YELLOW.**

**Progress:** ≈60% of `§Snapshot.1` scope is built end-to-end **in code**; measured-pilot capability
is ≈**0% live** because go-live is operator-gated. The periphery (multi-tenant + RLS, ingest,
auto-detect, A/B holdout math, onboarding, compliance, description pipeline) is done; the
**learning/measurement loops and signal richness — the differentiator — are the gap.**

**Top reasons for YELLOW:**

1. **Learning loop frozen in prod.** `FEEDBACK_ENDPOINT_ENABLED` 503-gates the feedback path →
   Thompson sampling is `Beta(1,1)` uniform-random; the bandit optimises nothing live (`§Snapshot.1`
   E.1–E.3; FOLLOW-450 code-complete, operator-pending).
2. **Affinity is a hash, not embeddings.** `archetype_embeddings.embedding` is seeded `NULL`; server
   reorder fails open to `deterministicScore` (djb2). The client cosine path is dead code (0
   callers). Personalised photo/listing ordering is deterministic-hash, not similarity.
3. **Signal starvation.** 25 of 52 event types are never emitted; `inquiry.completed` is queried by
   analytics but structurally can never arrive; Redpanda dual-write is a no-op so the chat-NLP
   `stream-consumer` gets zero prod traffic.
4. **Go-live is operator-gated, 0/6.** Feedback enable, ClickHouse migration apply, real API-key
   auth, chat deploy, embedding-seed run — all manual operator steps consolidated into FOLLOW-553;
   none done.
5. **Positives that carry the verdict up from RED:** no fabricated-metrics-on-error, no
   hallucinated-facts path, consent/opt-out enforced and not bypassable, tenant isolation clean,
   bundle in budget. The core is real and finishable.

**Answer to "if we finish on this foundation, will it work as intended?" → Yes.** The architecture
is coherent and the hard correctness properties (fact integrity, fail-loud analytics,
tenant/consent) already hold. The remaining work is _completion + operator go-live + signal
enrichment_, not a rebuild. But **it is not proven live today**, and a meaningful pilot cannot start
until the learning loop, affinity seed, and auth are switched on.

## 5. Findings by Severity

### 5.1 Bugs & logic

**F-01 | High | Analytics/SDK | `apps/control-plane/src/app/api/pilot/cta-lift/route.ts:172` +
`packages/sdk/src/core/adapt.ts:432-456`**

- **What's wrong:** `inquiry.completed` is a JOIN leg in the CTA-lift analytics query, but the SDK
  routes `inquiry.completed` only to `postFeedbackPing` (bandit feedback), never to `eventQueue` —
  so it can never reach the `events` table. The analytics leg is permanently empty.
- **Why it matters:** conversion-lift (the pilot's headline metric) silently under-counts inquiries;
  the dashboard implies a measurable funnel that isn't wired.
- **Fix:** either also `push` `inquiry.completed` into `eventQueue` in `handleOutcome`, or
  remove/annotate the analytics leg and derive completion from the feedback-ping table. Effort:
  **S**.

**F-02 | High | SDK | quiz-skip source-of-truth bug (QUEUE FOLLOW-554)**

- **What's wrong:** flagged in `§Snapshot.1`/QUEUE as a live SoT bug on the quiz-skip path
  (archetype persistence). Not independently re-traced in this pass — confirmed as an open queued
  P1.
- **Why it matters:** an incorrect SoT write corrupts the sessionStorage archetype that drives every
  subsequent adapt call (ADR-0014).
- **Fix:** execute FOLLOW-554 (sdk-engineer). Effort: **S/M**.

**F-03 | Low | Adaptation/LLM | `apps/llm-gateway/src/lib/llm-gateway.ts:239-295`**

- **What's wrong:** the directive-path prompts (`buildHaikuPrompt`/`buildSonnetPrompt`) lack the
  `<fact_whitelist>` contract that the description prompt has; grounding relies solely on the
  post-gen `checkDirectiveFacts` heuristic (digits + proper nouns). A hallucinated lowercase
  qualitative claim would pass.
- **Why it matters:** weaker guarantee on the directive path than the description path; hard facts
  (numbers) are still caught.
- **Fix:** port the description prompt's fact-whitelist rules into the directive prompts. Effort:
  **S**.

### 5.2 Architectural / conceptual

**F-04 | High | Intent Engine | `apps/intent-engine/src/main.py`,
`apps/stream-consumer/src/consumers/events.py:100`, `.github/workflows/modal-deploy.yml`**

- **What's wrong:** the 426-LOC Modal chat intent-engine is real and code-wired, but (a) CI deploys
  only `llm-gateway`, so `Function.lookup("estalara-intent-engine", …)` raises unless manually
  deployed, (b) the consumer swallows that error by design, and (c) it writes to a Redis **shadow**
  namespace only — the adapt route reads it but "does NOT influence directives" (`route.ts:1505`).
  Chat cannot change live adaptation.
- **Why it matters:** chat is a top-value signal for archetype accuracy; today it is captured and
  discarded in prod.
- **Fix:** deploy `apps/intent-engine` in the Modal CI phase; give it a prod transport that survives
  the Redpanda no-op (direct-Modal per ADR-0016, or Cloudflare Queue); then promote shadow → live
  behind DPIA gating. Effort: **M** (deploy) + **M** (transport).

**F-05 | High | Adaptation/Intent | `packages/db/migrations/0005_seed_archetype_embeddings.sql`,
`apps/control-plane/src/app/api/adapt/route.ts:581,610`**

- **What's wrong:** `archetype_embeddings.embedding` is seeded `NULL` ("filled by the Modal daily
  job"). Server reorder therefore fails open to `deterministicScore` (djb2 hash). The client-side
  cosine heuristic (`packages/sdk/src/core/embedding.ts`) has **zero callers** — dead code implying
  a capability that doesn't run.
- **Why it matters:** "affinity-based" photo/listing ordering is deterministic hashing, not
  similarity — the differentiator is cosmetic until vectors are seeded.
- **Fix:** run the embedding-seed Modal job in prod (operator — part of FOLLOW-553) and verify
  `computeCosineSimilarity` engages; either wire or delete `embedding.ts`. Effort: **S** (operator
  seed) + **S/M** (dead-code decision).

**F-06 | Medium | Intent Engine | archetype list duplicated in ≥6 files**

- **What's wrong:** the 18 IDs are hand-copied in `intent.ts`, `playbooks/index.ts`, `embedding.ts`,
  `shared/intent-weights.ts`, `0005_seed…sql`, and `apps/intent-engine/src/nlp.py`. Existing tests
  (`intent-weights-drift.test.ts`, `archetype_embeddings_seed.test.ts`) cover only pairwise subsets
  and re-declare the list. **No test asserts full-fan-out parity.** Add a 19th archetype in one
  place and CI stays green.
- **Why it matters:** latent drift risk on the product's core vocabulary; ADR-0006 enforces routing,
  not a single definition module.
- **Fix:** import all consumers from `shared` `ARCHETYPE_KEYS`; add one repo-wide parity test
  spanning SDK-union / playbook-registry / cosine-vectors / DB-seed / Modal-tuple (extends
  FOLLOW-561). Effort: **M**.

### 5.3 Missing pieces & dead ends (Rule H)

**F-07 | Medium | SDK/Ingest | `packages/shared/src/schemas/events/index.ts` (52 defined) vs SDK
emit (27)**

- **What's wrong:** 25 event types are pure dead schema — never emitted, so their `type` values will
  never appear in ClickHouse: `mouse.*`, `photo.opened/gallery.next/zoomed`, `floorplan.*`,
  `price.hovered/compared`, `search.query`, `sort.changed`, `chat.opened`, `chat.intent.detected`,
  `listing.next/compared`, `tour.requested`, `ab.assignment`, `sidebar.closed`, etc.
- **Why it matters:** archetype accuracy depends on signal richness; ~48% of the intended taxonomy
  is unreachable while the schema implies full coverage.
- **Fix:** prioritise wiring the high-signal types (photo gallery, price compare, chat.opened,
  tour.requested) end-to-end; prune or explicitly mark the rest as future. Effort: **L**.

**F-08 | High | Ingest | `apps/ingest/src/redpanda-producer.ts:82-88`, `apps/stream-consumer/*`**

- **What's wrong:** Redpanda dual-write is a documented no-op (`REDPANDA_REST_URL` empty in prod,
  ESC-017). The fully-implemented `stream-consumer` Modal app (real-time chat NLP) therefore
  receives zero prod traffic.
- **Why it matters:** the real-time intent path is dead in prod; combined with F-04, chat
  contributes nothing live.
- **Fix:** replace the Redpanda transport with the ADR-0016 direct-Modal dispatch (or a Cloudflare
  Queue → consumer) so `chat.message.sent` reaches `process_chat_message`. Effort: **M/L**.

**F-09 | Medium | Infra | ClickHouse prod migration apply**

- **What's wrong:** CH migrations are not auto-applied (only throwaway-container CI). Analytics
  assume `adaptation_decisions.holdout_group/variant/archetype/…` and the `intent_events` table
  exist in prod; if unapplied, queries 500 (loud) but the surface is down.
- **Why it matters:** operator-gated prod drift; must be applied before analytics/holdout produce
  data.
- **Fix:** apply the pending CH migrations via the operator console (FOLLOW-449/FOLLOW-553); add a
  `Rule M`-style prod-target check. Effort: **S** (operator).

**F-10 | Low | Intent/Infra | `packages/intent-ontology` (14-line stub),
`packages/platform-templates` (`[]`)**

- **What's wrong:** both are unbuilt placeholders with 0 consumers. `intent-ontology` promises a
  "12-dimension ontology" (TICKET-013); `platform-templates.matchPlatform()` always returns `null`.
  Neither blocks the pilot, but both inflate apparent readiness.
- **Why it matters:** Rule I (wired-or-dead) hygiene; misrepresents scope.
- **Fix:** either implement or clearly mark as not-started in `§Snapshot.1` (already 🟥) and remove
  dead exports. Effort: **S** (label) / **M** (build).

### 5.4 Performance & UX

**F-11 | High | Adaptation | `apps/control-plane/src/app/api/adapt/route.ts:341,362` +
`llm-gateway.ts:570,591`**

- **What's wrong:** `/api/adapt` branches 3 & 4 synchronously `await callLlmGateway()` (live
  Anthropic call, hundreds of ms–seconds) on the request path, plus a synchronous
  `getRolling24hSpend()` ClickHouse query before each call. Only branch 1 (default) and branch 2
  (high-similarity playbook) meet the <100 ms p95 budget.
- **Why it matters:** budget compliance depends on most sessions landing in fast buckets;
  medium/low-similarity sessions are over budget by design.
- **Fix:** move branches 3/4 to the async/precompute pattern already used by the description
  endpoint; cache/precompute the 24h spend. Reconcile the p95 bar with ADR-0004 (FOLLOW-564).
  Effort: **M/L**.

**F-12 | Low | Dashboard | `apps/control-plane/src/app/dashboard/quiz/analytics/page.tsx:1-14`**

- **What's wrong:** hardcoded `QUIZ_STATS` incl. a `+conversion_lift_pct%` "Inquiry Lift", disclosed
  only in the page subtitle — no mock badge on the tiles, no real-data path.
- **Why it matters:** an operator skimming could read a fabricated lift as real.
- **Fix:** add an explicit `MockDataBadge` on each tile (pattern exists on the main analytics page)
  or wire the real ClickHouse query. Effort: **S**.

**F-16 | Low | SDK | bundle headroom** — 40.49 KB gzip vs 42 KB budget (~3.6% headroom, narrowing).
Execute FOLLOW-469 (code-split/lazy-load) before adding SDK surface. Effort: **M**.

### 5.5 Privacy, security, compliance

**F-13 | Low | Security | `apps/control-plane/src/app/api/admin/labels/route.ts:136-139`**

- **What's wrong:** builds `AND model_version = '${x.replace(/'/g,"\\'")}'` (escape-only-`'`, the
  documented anti-pattern), currently neutralised by a preceding `/^[\w. -]+$/` allowlist. Injection
  is not reachable today.
- **Why it matters:** if the allowlist is ever loosened, this becomes injectable.
- **Fix:** bind as a ClickHouse `param_` value like the sibling queries. Effort: **S**.

**F-14 | High (uncertain) | Auth | QUEUE FOLLOW-555 "6 browser-session routes on `getAuthClaims`"**

- **What's wrong:** QUEUE flags 6 routes to move off `getAuthClaims`; this pass found the
  browser-session path correctly on `getUser()` and the `getAuthClaims` uses on Bearer routes
  (`detect`, `schema/activate`, `listings/embed`, `dsr/initiate`, `admin/labels`). Either the 6
  routes are elsewhere or the classification differs.
- **Why it matters:** trap #5 (cookie/claims mismatch → 40x) is the historical admin-login breaker;
  must be settled before pilot login traffic.
- **Fix:** FOLLOW-555 worker enumerates the exact 6 routes and confirms browser-vs-Bearer per route.
  Effort: **S** (audit) + **S/M** (fix if real).

**Positives (verified, no finding):** consent umbrella §H.8 + opt-out §H.9 enforced and not
bypassable; tenant isolation RLS `FOR ALL` + API 403; no committed secrets; no bare `any`.

### 5.6 LLM-generation integrity

**PASS.** `apps/llm-gateway/src/jobs/generate_description.py` enforces a layered `<fact_whitelist>`
(`:502-542`), the ADR-0010 NEUTRAL archetype-fit gate (refuses to spin a mismatched listing), a
`<verified_facts_used>` audit block logged to ClickHouse, and post-gen guards
(`_body_violates_contract`, truncation guard, `_check_headline_facts`). On any model
error/timeout/malformed output it **fails safe** — no Redis/Postgres write, endpoint serves
`template_fallback` (the agent's own copy), never empty/corrupted content. The ESC-019
ungrounded-generation gap is closed (route skips generation and fails loud to Sentry on missing
grounding, `description/route.ts:461-469`).

- **F-15 | Low:** a missing `<adaptation_verdict>` tag defaults to FIT
  (`_parse_adaptation_verdict:864`) — non-compliant responses are still gated by the body/truncation
  guards before caching, but the default should be NEUTRAL. Fix: default-deny. Effort: **S**.
