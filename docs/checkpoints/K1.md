   `/admin/*` only through `@supabase/ssr` `getUser()` against the production Supabase project (the
   sole account is the CEO's); no bearer/JWT path exists for pages. Decision owed before K3 (fold
   into M3 FOLLOW-1336): run Supabase Auth locally, or add a localhost-only session path that
   provably cannot exist in a production build.

   path 3 verifies HS256 against `SUPABASE_JWT_SECRET`, which neither Doppler `dev` nor
   `localhost-up.sh` provides. Devops change: `localhost-up.sh` generates a localhost-only
   `SUPABASE_JWT_SECRET` and passes it to the control plane and the spec (fold into FOLLOW-1233/1246
   bring-up hygiene or M3).

   step 10 (FOLLOW-1233/1246).
