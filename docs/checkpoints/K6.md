## The N3 record, including what failed

Three runs on one stack at `65580349`, not restarted between them:

1. **RED, 27/29.** `listing_save_revision`: the host backend sent the `listing-updated` webhook
   three times and timed out each time (`sends=3 status=null failure=timeout`), so the job stayed in
   `RETRY_WAIT`. The control plane logged the request as 200 in 4323 ms.
   `negative_analytics_refused`: a locator wait ran out at 120 s, so neither call of that control
   was made.
2. **RED, 13 cells.** The quiz card never opened (60 s wait), and every later cell failed with it.
   `OPTIONS /api/quiz/public-config` took 11088 ms in this window and other requests 2 to 14 s.
3. **GREEN, 29/29**, 05:35 to 05:40 UTC. The webhook calls answered 200 in 1050 and 1489 ms.

**Cause of runs 1 and 2: the machine, not the code (inferred, not proven).** Load average was 8 to
11 on 6 cores and 5.5 GB of 8 GB swap was in use. A container of another project
(`vc-test_storage_1`) was restarting every few seconds throughout. The PM did not stop it, because
it is not this project's. Run 3 GREEN on the same code and the same stack is the evidence of record.
Earlier, two bring-ups failed on PM-script errors (a stale fixture server on `:8081`; a PID file
that named the wrapper, not the node process); those runs measured nothing.
