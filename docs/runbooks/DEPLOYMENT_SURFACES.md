# Deployment surfaces — what ships automatically, what does not, and how to tell

**Status:** living register · **Owner:** devops-engineer · **Created:** 2026-08-10 (FOLLOW-938)

## Why this file exists

In one merge window, two PRs closed `DONE` on **identical evidence** — a merge commit plus
`scripts/gh-pr-checks-verified.sh` exit 0 — with **opposite deployment outcomes**. #710 landed in
the control plane and was observably live within hours; #711 landed in the ingest Worker and was not
deployed at all. Nothing distinguished them, because **the closure criterion has no deployment
axis** and no probe could report what was running.

Merging is not shipping on every surface in this estate. This table says which.

### Corrections this register made to the record

- **`modal-deploy.yml` ships THREE apps, not one.** Several places (including FOLLOW-938's own stub
  and the session-99 memory) say _"modal-deploy.yml ships only llm-gateway"_. It has three real
  deploy steps — `llm-gateway`, `intent-engine`, `data-quality/schema_validation` — on push to
  `main`, path-filtered. That claim is stale wherever it still appears.
- **`apps/control-plane/public/sdk.js` is NOT a tracked build artefact.** FOLLOW-938 AC(5) records
  it as tracked-and-stale at 155,056 B. It is gitignored and untracked; `git log` shows FOLLOW-808
  (`39d7acb7`) is where it became generated-on-build. There is nothing to refresh or ignore, and no
  stale answer for anyone grepping it.

## The ingest deploy question (AC 3) — recorded, not re-filed

**Decision recorded here: the production ingest deploy STAYS a gated operator step for now, and is
now TRACKED, which is the half that was actually missing.** The stub's complaint was precise — _not
automated and not tracked_ — and the second is the defect. `GET /health` now answers the question a
probe could not previously ask.

Automating it is a live open question and belongs to **ESC-043 item 4**; it is referenced here, not
re-filed. Whoever takes it should weigh: the Worker sits in front of every event the product
collects and has no staged rollout, while the control plane's auto-deploy has a rollback button that
the Worker path does not.

## Closure criterion for manually-deployed surfaces

See `docs/TICKET_FORMAT.md` → **`MERGED_NOT_DEPLOYED`**. A ticket whose fix lives in any row above
marked **NO** is not `DONE` on merge.
